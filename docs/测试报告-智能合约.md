### 性能解读（**答辩时可以直接讲**）

1. **核验是免费的**。`verifyWork` 为 `view`，评委打开网页核验一份文件**不花任何 gas、不需要有钱包**——这是"任何人都能独立验证"的技术前提。
2. **一次存证约 24.4 万 gas**。以 Sepolia 测试网计几乎为零成本；即使在主网按 20 gwei 估算，也远低于一笔普通转账的复杂度量级。
3. **O(1) 核验**。`hashToWorkId` 是 mapping 直查，核验成本**不随存证总量增长**——这是支撑"长期可用"的关键设计。
4. **`registerWork` 是唯一重函数**，因为要写入完整结构体 + 2 个 mapping + 1 个事件。已用 `unchecked` 计数器与 custom errors 优化，进一步压缩需牺牲可读性，**不划算**。

## 六、安全测试清单（PPT 要求"安全测试"，人工分析 + 已用测试覆盖）

| 风险 | 分析结论 | 测试证据 |
| --- | --- | --- |
| **重入攻击** | **不适用**。合约**没有任何转账/外部调用**，不存在重入路径 | 代码审查（无 `.call` / `.transfer` / 外部合约调用） |
| **整数溢出 / 下溢** | Solidity **0.8+ 内置检查**；计数器用 `unchecked` 处已论证不可能溢出（`workCount` 需 2^256 次调用） | 组2 边界值用例 |
| **权限控制** | 改动类操作全部受 `onlyWorkAuthor` 保护；`admin` 为 `immutable` 不可篡改 | 组5/组6 的 `NotAuthor` 用例（3 个） |
| **越权登记 / 确权冲突** | `hashToWorkId` 唯一性保证一份指纹只能归属一个成果 | 组3 `AlreadyRegistered` + 组5 确权冲突用例 |
| **输入校验缺失** | 零哈希、空标题、比例越界、相同指纹 **4 类非法输入全部拒绝** | 组3 + 组5（共 5 个用例） |
| **拒绝服务（DoS）** | 无循环依赖用户输入；`getWorkCountOf` 为只读函数，不上链，不构成 DoS 面 | 组8 |
| **前端 XSS** | 待阶段4 前端完成后补测：所有链上字符串经 Vue 模板插值（默认转义），不使用 `v-html` | ⏳ 阶段4 |
| **私钥管理** | **私钥只存在于本地 `.env`，已被 `.gitignore` 屏蔽**；部署使用专用测试钱包，杜绝真实资产风险 | 见 `blockchain/.env.example` 注释 |
| **可升级性风险** | 合约**不可升级**（无代理模式）。这是**有意选择**：存证的可信度正来自于"不可篡改、不可偷偷改逻辑" | 架构决策，写入文档 |

> **可选加分**：装 [Slither](https://github.com/crytic/slither) 跑一次静态分析并截图为佐证。但 Slither 需要 Python 环境（**你机器上目前没有 Python**），装环境约 30-60 分钟。**建议 10-02 之后有余力再做**，优先级低于前端。
