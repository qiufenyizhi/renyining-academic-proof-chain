## 二、性能测试：前端哈希耗时（**需要你操作**）

### 2.1 怎么测

1. 打开浏览器访问：**http://127.0.0.1:5173/perf-test.html**
2. **先点「开始测试」**（页面第②块）—— 这会自动生成 1/10/50/100/200 MB 的随机数据并各算 3 次，测的是**纯计算耗时**
3. **再用真实文件测**（页面第③块）—— 点「选择文件」，选中若干个真实文件（建议有 10MB 左右的、50MB 左右的）
4. 两段结果都会自动生成 Markdown 并显示在页面上，**点「复制 Markdown 表格」**，粘贴给我

> ⚠️ **为什么要测两种？**
> - **合成测试**只测 `crypto.subtle.digest` 计算 → 说明"计算本身不是瓶颈"
> - **真实文件测试**额外包含 `file.arrayBuffer()` 读取 → **这才是用户真实感知的耗时**
>
> **提案书里应以真实文件的数字为准**，合成数据作辅助说明。

### 2.2 预期会得到什么

| 数据项 | 用途 |
| --- | --- |
| 各尺寸文件的哈希耗时（毫秒） | 填进提案书第 4 章「性能测试」 |
| 吞吐率（MB/s） | 证明本地计算速度足够，不需要上传 |
| 测试环境信息（浏览器/CPU/内存/显卡） | 测试报告必须交代环境，否则数据不可信 |

### 2.3 对结果的初步预期（先给你一个判断基准）

- 现代浏览器 SHA-256 通过 Web Crypto（原生实现）通常能到 **数百 MB/s**；
- **10MB 文件预计 30-80 ms，100MB 预计 300-800 ms**，都在 1 秒内；
- 如果 100MB 超过 3 秒，告诉我，可能是浏览器版本或内存问题，需要换个说法。

> **这个数据的意义**：证明用户"拖入文件 → 看到指纹"几乎无等待，因此**不需要上传到服务器再算**——
> 这从性能角度直接支撑了「文件不上传」这个核心设计。

## 四、安全测试清单（人工分析，**已分析完，请你复核确认**）

| 风险项 | 分析结论 | 验证方式 |
| --- | --- | --- |
| **重入攻击** | **不适用** —— 合约无任何转账与外部调用，不存在重入路径 | 代码审查 |
| **整数溢出/下溢** | Solidity 0.8+ 内置检查；使用 `unchecked` 的计数器已论证不可能溢出 | 单元测试 组2 |
| **权限控制** | 改动类操作均受 `onlyWorkAuthor` 保护；`admin` 为 `immutable` | 单元测试 组5/组6（3 个 `NotAuthor` 用例） |

| **输入校验** | 零哈希、空标题、比例越界、相同指纹 —— 4 类非法输入全部拒绝 | 单元测试 组3 + 组5（共 5 个用例） |
| **拒绝服务** | 无循环依赖用户输入；`getWorkCountOf` 为只读函数不上链 | 代码审查 |
| **前端 XSS** | 所有链上字符串经 Vue 模板插值（默认转义），**未使用 `v-html`** | 代码审查（见下方 4.1） |
| **私钥管理** | 私钥仅存于本地 `.env`，已被 `.gitignore` 屏蔽；使用专用测试钱包 | 已全仓库扫描确认无泄露 |
| **可升级性风险** | 合约**不可升级**（无代理模式）—— 这是有意选择：存证可信度正来自"不可偷偷改逻辑" | 架构决策 |

### 4.1 XSS 验证（建议你执行一次）

链上标题是**用户可控字符串**，理论上可写入 `<script>` 之类内容。验证步骤：

1. 登记一个成果，标题填：`<img src=x onerror=alert(1)>`
2. 打开核验页核验该文件，以及打开详情页
3. **预期**：标题**原样以文字显示**，不弹窗、不执行
4. 若确有弹窗 → 存在 XSS 漏洞，立即告诉我

> 这是**唯一需要动手验证的安全项**，其余均为代码审查结论。
