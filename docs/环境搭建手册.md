原因：`hardhat-toolbox` 有**两条线**——`latest`（7.x）和 `hh2`（6.x）都是给 **Hardhat 3** 用的，而 `5.0.0` 是给 Hardhat 2 用的且只接受 gas-reporter v1。

### ⚠️ 已踩坑并修复：真实网络的自定义 error 判定（**务必知道，否则会白排查半天**）

**现象**：在本地链上自检全绿，但换到 `--network sepolia` 后出现

```
❌ 重复指纹登记被拒（AlreadyRegistered）
❌ AIGC 比例 > 100 被拒（InvalidRatio）
```

**根因**（2026-09-24 实测确认）：**同一个 revert，本地链与真实网络给出的报错形状完全不同**。

| | `e.message` | 自定义 error 名在哪 |
| --- | --- | --- |
| 本地 hardhat | `VM Exception while processing transaction: reverted with custom error 'AlreadyRegistered()'` | **就在 message 里** |
| 真实 Sepolia | `execution reverted`（**不含错误名！**） | **只在 `e.data` 的 4 字节选择器里**，如 `0x3a81d6fc` |

原脚本用 `String(e.message).includes("AlreadyRegistered")` 判定，**在真实网络上必然失败**——这不是网络问题，也不是合约问题，纯粹是**本地节点帮忙把错误名解码填进了 message，而公共 RPC 不会**。

**修复**（`scripts/check-env.js`）：
1. 从合约 ABI **现算**各自定义 error 的选择器（`frag.selector`），建立 `选择器 → 错误名` 映射；
2. 捕获异常后优先从 `e.data` 取选择器比对，message 只作兜底；
3. 所有"预期失败"的调用一律改用 **`staticCall`**——只做链上模拟，**不上链、不花 gas、不占用 nonce**。

**修复后**：`--network sepolia` 自检 **6 组 27 项全部通过**。

> **这条经验值得写进设计文档的"测试与分析"章节**：它说明测试用例必须在**目标环境**验证，本地绿不等于线上绿。这也是"技术规范"里的加分素材。

**顺带记录一个失败尝试**：曾试图配置 `sepolia_fork`（本地分叉真实测试网）来离线复现上述问题，但本版 Hardhat（2.29.1 / EDR 0.3.8）**对具名网络无法启用 forking**——`hardhat_setBalance`、`hardhat_metadata` 一律返回 `Method not found`，即使加了 `chainType: "hardhat"` 也无效。**结论：验证真实网络行为就直接跑 `--network sepolia`**，不要在这个方向上耗时间。该配置已从 `hardhat.config.js` 移除。

## 四、合约相对原清单做的 6 处加固（**要写进设计文档的"详细设计"**）

原清单第 3.2 节的合约是可用草稿。我在实现时发现并修掉了 5 个真实问题，外加 1 项工程化增强。这些都是**答辩时能讲出深度的地方**，也是"详细设计"章节的素材：

| # | 问题 | 修复 | 为什么重要 |
| --- | --- | --- | --- |
| 1 | `addVersion` 可直接挪用**已属于他人成果的指纹**，造成"一稿两证" | 追加前检查 `hashToWorkId[_contentHash]`，若已归他人则 `revert AlreadyRegistered()` | 这是真实的**确权冲突漏洞**，涉及作品核心正确性 |
| 2 | `addVersion` 允许提交与当前版本**完全相同的指纹** | 新增 `SameHash` 错误并拒绝 | 防止刷 `versionCount` 伪造"多次迭代" |
| 3 | 允许登记**全零指纹**（`bytes32(0)`） | 新增 `ZeroHash` 错误 | 零值会让 `verifyWork` 产生歧义 |
| 4 | 允许登记**空标题** | 新增 `EmptyTitle` 错误 | 核验页面会显示空标题，演示时很难看 |
| 5 | `raiseDispute` **任何人都能对任意成果标记争议**且不可撤销 | 保留开放性（设计如此，符合"第三方可质疑"），但**明确写入文档**：这是 demo 的有意取舍，生产环境需引入质押/仲裁机制 | 评委会问"恶意标记争议怎么办"——**主动说明取舍比被问倒好** |
| 6 | `admin` 可被修改（`address public admin`） | 改为 `address public immutable admin` | 省一次 SLOAD，且**消除"管理员偷偷换人"的信任假设**，与"不依赖平台自证"的产品定位一致 |

另外把 `workCount++`、循环计数等改为 `unchecked`（Solidity 0.8 已内置溢出检查，但计数器不可能溢出），**gas 优化可写进性能测试章节**。

还有一处**刻意保留的设计**：`hashToWorkId` 在 `addVersion` 时会**覆盖**旧版本指纹的映射吗？——不会。旧版本指纹仍然指向同一个 `workId`，所以**历史版本也能核验通过**（自检脚本第 6 组专门验证了这一点）。这是"过程留痕"的技术支撑。
