## 一、这个视频只证明一件事

> **同一份文件核验通过；改一个标点，核验立刻失败——而且这一切不依赖任何中心平台的信用。**

所有镜头都为这一句话服务。**任何不能强化这句话的镜头，删掉**（不要放数据看板滑来滑去、不要放 loading 动画、不要放个人介绍）。

### 三条必须让评委看到的信息（缺一条就要重录）

1. **文件没有上传服务器** —— 浏览器本地计算 SHA-256（演示时故意断网也能算出来）
2. **指纹上链了**，链上能查到（Etherscan 截图或前端交易链接）
3. **改一个标点就核验失败** —— 戏剧性的一刻

## 三、逐秒分镜表（**照着念就行**）

### 【0:00 - 0:15】开场：抛出问题（首页）

| | |
| --- | --- |
| **画面** | 应用首页。标题「科研链证」，副标题「基于区块链的学术成果原创性与AIGC贡献存证平台」。鼠标静止 |
| **旁白** | "评委老师好。查重报告只有平台自己说了算，AI 到底代写了多少也无据可查——**这些结论，第三方没法独立验证**。我做了一个不依赖平台信用的存证与核验服务，叫科研链证。" |
| **要点** | 15 秒内说清**痛点 + 一句话定位**，不要说"我用了什么技术栈" |

### 【0:15 - 0:25】连接钱包（首页 → 弹窗）

| | |
| --- | --- |
| **画面** | 点击「连接钱包」→ MetaMask 弹窗 → 点「连接」→ 右上角显示地址缩写 `0x1a2b...3c4d` |
| **旁白** | "身份就是钱包地址，**不需要注册，平台也不掌握任何用户密码**。" |
| **要点** | 这条直接对应"❌ 不做用户注册系统"的设计决策，**主动讲出来显得你想得清楚** |

### 【0:25 - 1:00】存证登记：本地算指纹（`/register`）

| | |
| --- | --- |
| **画面** | 拖入 `科研链证-演示论文-v1.docx` → 页面上**哈希值飞快滚动后定格**（如 `0x7f3a9c...`）→ 填标题、类型选「论文」→ AIGC 声明填「ChatGPT-4o，辅助润色，占比 20%」 |
| **旁白** | "我把论文拖进浏览器。**请注意，这里的指纹是浏览器用原生 crypto 本地算出来的**——`SHA-256`，文件从头到尾**没有上传到任何服务器**。" |
| **旁白** | "然后我如实声明：这篇论文用 ChatGPT 做过润色，介入比例约 20%。**这个声明一旦上链，事后无法改口。**" |
| **画面** | 点击「提交存证」→ MetaMask 确认 → 成功动画 → 显示 **workId = 1**、**链上时间戳 2026-10-04 14:32** |
| **旁白** | "现在它上链了，得到成果编号 1 和**链上时间戳**。注意这个时间是矿工写入的，**我本人改不了**。" |
| **要点** | ⭐ **关键动作：提交前把浏览器切到飞行模式或断网 3 秒，证明哈希仍能算出。** 这个镜头极有说服力（可选，但强烈建议） |

### 【1:00 - 1:20】链上留痕（切到 Etherscan）

| | |
| --- | --- |
| **画面** | 切到 Etherscan 合约页 → 展示 `WorkRegistered` 事件日志 → 鼠标指向 **Block / Timestamp / From / contentHash** 四列 |
| **旁白** | "这是链上的公开记录。**任何人不需要信任我，直接查链就能看到这笔存证**——包括指纹、我的地址和写入时间。我的平台自己都改不了它。" |
| **要点** | 这一镜是"**不依赖平台自证**"的物证。若时间紧张，此镜可压到 12 秒 |

### 【1:20 - 1:50】核验通过（`/verify`）—— 切换为"核验方"角色

| | |
| --- | --- |
| **画面** | 点击导航「核验」→ 页面提示「当前身份：核验方（期刊 / 竞赛组委会）」→ 拖入**同一份** v1 文件 |
| **旁白** | "现在切换身份。假设我是期刊编辑，拿到作者发来的论文。我把它拖进核验页。" |
| **画面** | 大字结论浮现：**✅ 核验通过** ／ 该文件与链上登记记录**完全一致** ／ 作者 `0x1a2b...3c4d` ／ 登记时间 2026-10-04 14:32 ／ AIGC 比例 20% |
| **旁白** | "核验通过。作者、登记时间、AIGC 声明全部来自链上。**整个过程没有向我的服务器发送任何数据。**" |
| **要点** | 「核验方」不能用作者的钱包身份出现在画面上——所以**页面上要有明确的角色提示条**（这是前端需求，记进阶段4） |

### 【1:50 - 2:20】⭐ 篡改即失效（全片高潮）

| | |
| --- | --- |
| **画面** | 切到 Word/WPS，打开 v1 文件 → **放大到一个句号** → 改成逗号 → 保存 → 关闭 |
| **旁白** | "现在，我在论文里**只改一个标点**——把句号改成逗号，其他一个字都没动。" |
| **画面** | 回到核验页 → 拖入改动后的文件 → 短暂的"计算中" → 大字结论浮现：**❌ 核验失败** ／ 该文件与链上任何登记记录均不匹配 |
| **旁白** | "核验失败。**内容几乎是同一篇，但指纹完全不同。** 这就是区块链存证的意义：任何改动都藏不住。" |
| **要点** | ⭐ 此处**停 2 秒不说话**，让画面自己说话。这是全片最强的 3 秒 |

### 【2:20 - 2:40】存证证书 + 履历时间轴（`/work/1`）

| | |
| --- | --- |

### 【2:40 - 3:00】收尾：为什么必须是区块链

## 五、对前端的需求反推（**录屏前必须实现，写进阶段3~4 验收**）

这张表是**演示脚本倒推出来的功能需求**，比任何功能列表都准确。前端开发时逐条对照：

| 编号 | 需求 | 服务于哪一镜 | 优先级 |
| --- | --- | --- | --- |
| D1 | 上传后**实时显示哈希**（含计算耗时毫秒数） | 0:25 | 必须 |
| D2 | 页面明确标注「文件未上传，本地计算」 | 0:25 | 必须 |

| D4 | 核验结果**大字**：✅ 核验通过 / ❌ 核验失败 | 1:20 / 1:50 | 必须 |
| D5 | 核验通过时展示作者地址、登记时间、AIGC 比例、标题 | 1:20 | 必须 |
| D6 | 页面上有**角色提示条**（作者 / 核验方） | 1:20 | 必须 |
| D7 | 详情页时间轴（登记 → AIGC → 版本 → 争议） | 2:20 | 必须 |
