# 结语

## 我们做了什么

**科研链证**是一个**独立第三方存证与核验服务**。

它不替代任何写作或投稿平台。作者在任何地方写完论文、代码，都可以在这里留下一个不可篡改的**内容指纹**；
任何评审方、期刊、竞赛组委会都能**独立验证**其原创性与 AI 使用情况，**而不需要信任存证平台本身**。

具体而言，本作品交付了：

| 交付物 | 状态 |
| --- | --- |
| 智能合约 `AcademicProof`（约 250 行，含 6 处安全加固） | ✅ 已部署至 Sepolia 并通过 Etherscan 源码验证（`Exact Match`） |
| 34 个单元测试用例，覆盖率 100%（语句/分支/函数/行） | ✅ 全部通过 |
| Vue3 前端应用（5 个页面）+ 以太坊浏览器端交互 | ✅ 已通过浏览器端到端人工验证 |
| 测试数据：gas 消耗表 + 哈希耗时表 + 功能用例表 + 安全清单 | ✅ 已完成 |
| 提案书（选题定位 / 概要设计 / 详细设计 / 实现现状 / 测试与分析 / 价值前景） | ✅ 已完成 |

## 三个最核心的判断

### 一、文件永不上传服务器

浏览器使用 Web Crypto API 在本地计算 SHA-256，只有 32 字节的指纹上链。
**原文不经过任何网络请求。**

实测数据：100 MB 文件的本地计算端到端耗时 **208 毫秒**，吞吐率约 **1.5 GB/s**。
同一文件若走上行传输（普通宽带 20 Mbps）需约 **40 秒**——**约 190 倍差距**。

因此这一设计不只是隐私选择，**也是体验与成本的更优解**。它同时消除了使用者最主要的顾虑：
"把我的论文传到别人服务器上安全吗？"

### 二、核验不需要许可，也不需要信任

`verifyWork` 是 `view` 函数，**核验 0 gas、不需要钱包、不需要注册、不需要登录**；
底层是 mapping 直查，**核验成本不随存证总量增长**。

任何第三方拿到文件后，用任何工具重算 SHA-256，再到链上查询该指纹是否存在即可。
**整个过程不需要访问本作品的服务器，也不需要信任本作品。** 即使平台停止运行，验证能力依然存在。

### 三、把"信任"替换为"校验"

本作品最本质的一点不在某个功能，而在一个结构性改变：

> 中心化存证中，**记录方就是验证方**，第三方只能选择相信；
> 本作品中，**记录方与验证方分离**，第三方可以自行校验。

平台拿不到原文（文件不上传）、改不了记录（合约无任何修改接口，`admin` 为 `immutable` 且不参与权限判定）——
**平台自己也无法作恶**。

## 我们对完成度的态度

本次开发与测试过程中，共**发现并修复了 6 个真实问题**，包括：

- 本地链测试全绿、但切换真实网络后失败的**自定义错误判定差异**
- 导出的存证证书**中文全部乱码**（jsPDF 标准字体不含中文字形）
- 依赖版本冲突、模板引用未定义标识符、误导性界面文案、文档措辞与代码不符

这些问题都记录在文档中，**含修复前后的对比**。

同时，我们也**主动说明了尚未完成的部分**：

| 未完成项 | 说明 |
| --- | --- |
| **AIGC 工具名称未在登记时上链** | 当前链上只有 AIGC 介入比例；工具名称需另行补写。已在界面如实标注，并提供补写入口 |
| 时间轴历史事件时间精度 | 用"最近更新时间"近似，页面已注明 |
| 争议机制只做登记、不做裁决 | 完整治理需引入质押与多方仲裁 |
| 四项加分项 | 联盟链部署、云平台部署、静态安全分析、第三方测试报告——**均为规划中，未实现** |

> **我们选择如实记录问题与未完成项，而不是只呈现"全部通过"的结果。**
>
> 原因有两层：其一，一份隐瞒问题的报告，其"完成度"信息也就失去了参考价值；
> 其二，**"发现问题 → 定位根因 → 修复 → 验证"的完整链条本身就是工程能力的体现**，
> 比一份未经真实检验的全绿报告更有说服力。

## 一句话总结

> **我们不试图做一个更好的查重工具，而是尝试把"证明"这件事，从机构手中交回给数学。**

科研链证 —— 不替代任何写作或投稿平台，只做那一层**谁都无法作假的指纹与时间**。
